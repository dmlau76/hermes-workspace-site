Privacy Policy

Hermes Workspace Integration · last updated 11 November 2026

Hermes Workspace Integration ("the integration") is a personal automation client operated by a single individual for his own Google account. This policy describes what it accesses, where that data goes, and how access can be revoked.

Whose data

Only the operator's own Google account. The integration has no other users, does not accept sign-ups, and does not access data belonging to anyone else.

What is accessed

  • Gmail — reading, searching, labelling, and sending messages in the operator's own mailbox.
  • Calendar — reading and creating events on the operator's own calendars.
  • Drive — reading, creating, organising, and deleting files in the operator's own Drive, including encrypted backups.
  • Docs — reading and editing the operator's own documents.
  • Basic account identity — the account email address, used only to route OAuth tokens to the correct account.

Where data is processed and stored

Processing happens on computer hardware owned and administered by the operator. Messages, calendar entries, and documents are held in memory only for the duration of a task and are not copied to any third-party storage service.

When the operator asks for AI-assisted work (for example, summarising a message or drafting a reply), the content needed for that task may be sent to the AI model provider configured for it. Those requests are made only on the operator's explicit instruction, never automatically in the background.

The integration does not use any analytics, advertising, tracking, or profiling service, and it does not share, sell, rent, or disclose Google user data to any third party for advertising or resale. Data is transferred only to Google's own APIs and, as described above, to the AI providers the operator has configured.

Credentials

OAuth refresh tokens are stored in an encrypted keyring file on the operator's own hardware, readable only by the account that runs the integration. Google account passwords are never requested or stored.

Backups

One task makes an encrypted backup of a self-hosted password manager and uploads the encrypted archive to the operator's own Google Drive. The archive is encrypted with symmetric AES-256 before it leaves the operator's hardware; Google stores ciphertext only. Backups older than the retention window are moved to the Drive trash. This backup contains no data from any other Google user.

Retention and deletion

No derived copy of Google data is retained beyond the task that used it. Encrypted backups are retained on a rolling basis and can be deleted at any time from the operator's Drive. Removing the integration's access stops all further processing immediately.

Revoking access

Access can be revoked at any time at myaccount.google.com/permissions. Revoking access invalidates the stored refresh token, and the integration stops working immediately.

Google API Services User Data Policy

The integration's use of information received from Google APIs adheres to the Google API Services User Data Policy, including the Limited Use requirements.

Changes

If this policy changes, the revised version will be published on this page with a new "last updated" date.
